## How the book is organized

- **Flavor:** hands-on book and course (HTML / A11Y), not tools-heavy SEO and not an exam study guide. Every chapter has TypeScript snippets. CodeSandboxes are required once examples exist.
- **The book is `README.md`.** No `chapters/` tree.
- **Audience:** coding-interview prep. Teach the structure or pattern, then solve interview questions in TypeScript. Not a CS textbook.
- **Heading recipe:** `##` chapter, `###` section, `####` subsection, `##### Example: …` for each worked problem. Every `##` ends with `### Summary: {Exact Chapter Title}`. No `Conclusion` headings. No case studies.
- **Suggested H1:** `# 📚 Awesome DSA Book & Course: Data Structures and Algorithms (DSA)`
- **Suggested repo:** `Awesome-DSA-Book-Course-Data-Structures-and-Algorithms` (current GitHub repo is the `Awesome-DSA` stub).
- **Language:** TypeScript throughout (classes, references, types for `ListNode` / `TreeNode`, `Map` vs `Record`, sort comparators, `Set`).
- **Close:** Common Challenges, Additional Resources, then Appendix A–D (A11Y-style). Hash collisions live in the Hash Tables chapter and again in Appendix A.

TOC rules from the Ditectrev skill: heading-anchor links only, plain tool names, include every `Summary:`, match body heading strings exactly.
